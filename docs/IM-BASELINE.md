# AgentChat：真人 IM 优先

1. 真人 IM：独立前端构建/运行，独立后端 HTTP + WebSocket；两个独立真人账号通过实际 UI 在同群收发、撤回、交换图片/文件及录制语音。WebSocket 只通知刷新，SQLite 是消息的来源；断线重连从后端补齐。每个浏览器会话独立鉴权。
2. 存储：独立构建/测试的对象存储模块负责字节，后端负责消息、成员和附件授权。先实现单机目录；不把第三方云盘分享链接当作权限控制。后续对象存储/云盘适配器不得绕过同一接口与授权检查。
3. 真人 IM 浏览器验收后才接入 Agent MCP 独立模块；智能编排在 Agent 接入后验收，不以支架、提示或模拟会话冒充真实上线。

首个浏览器门禁针对 Chromium 和录音消息，不假定语音通话、跨设备麦克风、移动端、线上存储或完整邀请生命周期已实现。存量桌面预览继续走原入口，正式部署需更新启动/回滚包以安装锁定依赖并运行前后端两个进程；验证期间不覆盖旧预览。

## 传统 IM 补齐顺序

1. **好友与私聊**：真人按名称搜索，发起申请后由对方明确接受，才可打开固定双人私聊。私聊不对第三人、工作区管理员或 Agent 开放；即使名称重复，也以账户 ID 区分。现有密钥登录模式保留，本轮不新增自助注册。
2. **未读与同步**：服务端按真人账户与会话记录已读位置；不复用 Agent 消费游标。只在前台会话渲染到相应位置后确认已读。私聊重连补齐跨页消息及旧消息的撤回状态；其他会话的未读不因此清除。
3. **下一轮**：群主／管理员／成员权限、邀请审批及历史行为，使用三个独立真人账号验收。平均端到端送达 ≤200 ms、台式机及 Tailnet HTTPS/WSS 尚需独立验证。
